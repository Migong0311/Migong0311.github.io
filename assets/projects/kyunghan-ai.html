01 / PROJECT OVERVIEW

현장 신호를 해석 가능한 AI 결과로

경한코리아 AI실증에서 다룬 두 가지 모델 접근과 개발 과정을 기록합니다.

CNC에서 수집된 Spindle, RPM, Feed, Offset, Cycle 등의 공정신호를 사용해 공구와 설비의 이상 상태를 분석하고 Raspberry Pi에서 추론하는 프로젝트입니다. 데이터 확보부터 모델 학습, TFLite 변환, 모델 이력 관리와 현장 배포까지 연결된 개발 항목을 다룹니다.

이 페이지는 BONE AI4M의 IF+AE 공구별 이상탐지와 TOOL_BREAK v6의 약지도 파손 위험점수 모델을 별도 기술 기록으로 구성했습니다. 이름이 비슷한 이상점수라도 학습 방식과 평가 기준이 다르므로 서로의 설정이나 성능을 혼용하지 않습니다.

DATA ENGINEERING

DB 조회와 Python 전처리 분리

DB에서는 기간·설비·O-Number 조건과 Hash 표본을 처리하고, Python에서 타입 변환·유효성 검사·MAIN/SUB ACTIVE 판정을 수행합니다.

각 Side의 RPM 또는 Feed가 0보다 크면 ACTIVE로 판정합니다. Snapshot에서 공구별 데이터를 분리하므로 공구마다 DB를 다시 조회하지 않습니다.

MODEL GRANULARITY

공구별 위치와 설비 전체를 함께

MAIN·SUB는 Tool No별로 모델을 나누고, 별도의 OVERALL 모델이 전체 공정의 이상도를 생성합니다. O-Number는 모델 분리 키가 아니라 범주형 입력입니다.

공구 데이터가 2,000건 미만이면 학습을 건너뜁니다. 모델이 없는 공구에는 다른 공구 모델을 대신 적용하지 않습니다.

A1 · §6–11·24

IF와 AE를 결합하는 이유

ISOLATION FOREST

드문 신호 조합을 찾기

공구별 정규화 Feature가 정상 분포에서 얼마나 고립되어 있는지 점수화합니다. FIT 구간 IF 점수의 95백분위 이하를 AE 학습용 Normal Core로 사용합니다.

AUTOENCODER

정상 패턴을 복원하기

Normal Core를 압축·복원하도록 학습합니다. 평소와 다른 입력을 잘 복원하지 못할수록 MSE 복원오차가 커지는 구조입니다.

IF_pct = IF raw score의 Calibration 백분위
AE_pct = AE 복원오차의 Calibration 백분위

Fusion = 0.60 × max(IF_pct, AE_pct)
       + 0.40 × mean(IF_pct, AE_pct)

anomaly_score = Fusion의 Calibration 백분위 (0–100)
정상0–89.99일반적인 분포
관찰90–94.99추세 관찰
주의95–97.99점검 권고
이상98–100파손 의심 / 공정 이상
98점은 파손확률 98%가 아닙니다. Calibration 분포의 상위 약 2% 경계라는 뜻입니다. 기준알림률 약 2% 역시 실제 오탐률 2%를 뜻하지 않습니다.

A1 · §12–18

학습·전처리 설정과 Feature 변경 시 주의사항

수치형 결측치는 median으로 보완하고, median·IQR 기반 정규화와 −12~+12 Clip을 적용합니다. IQR이 작으면 Std를 사용합니다. 시간순 앞쪽 약 80%를 FIT, 뒤쪽 약 20%를 Calibration으로 나눕니다.

IF는 128 Trees, max_samples 최대 4,096입니다. AE는 Adam(1e−3)·MSE, 최대 60 Epoch, Batch 256, EarlyStopping patience 5 설정이며 최대 학습행은 100,000입니다.

Servo 제거는 입력 벡터와 산출물의 버전 변경입니다. Pi 코드만 바꾸지 않고 재학습·TFLite 재변환·runtime/meta/index 재배포를 함께 수행해야 합니다.

A1 · §5·12–15

Pi에서는 신규행만 처리

마지막 처리 위치 (ins_dt, seq)를 Watermark로 관리하고 그 이후 신규행만 읽습니다. 각 행의 MAIN·SUB 활성 여부와 현재 Tool을 확인해 해당 모델과 OVERALL 모델을 실행합니다. 모델 runtime은 캐시하여 매 행마다 파일을 다시 읽지 않습니다.

Polling 0.25초, 한 번에 최대 200행은 조회 설정입니다. 추론 지연시간 보장값이 아닙니다. 원문의 JSON 예시에는 inference_ms가 있지만 평균·최대 현장 추론시간을 입증하는 시험 결과로 일반화하지 않았습니다.

A1 · §23–25

05 / TOOL_BREAK v6 · RISK-ONLY

공정신호를 학습한 경량 파손 위험점수 모델

문서 기준: 2026.08.19 · Cycle Summary와 Weak Supervision

Raw 한 행이 아닌, 공구별 Cycle을 학습 단위로

약 1초 수준으로 수집된 Raw를 MAIN/SUB Long 형식으로 펼친 뒤 iot_seq + main_seq + side + O-NUM + Tool No로 묶습니다. Cycle의 평균·최대·변화량·안정성을 고정 길이 Feature로 요약하여 경량 MLP에 입력합니다.

01Cycle Summary부하 · RPM · Feed · Offset · Cycle
02Feature + Weak Label25개 기본 Feature + One-Hot · 규칙 기반 위험점수
03MLP → TFLite해당 실행 35 → 24 → 12 → 1 · Pi 위험도 추론
FEATURE ENGINEERING

현재값 + 평소값 + 변화량

같은 설비·Side·O-NUM·Tool의 이전 10 Cycle을 기준선으로 사용합니다. 가이드에는 shift(1)을 먼저 적용하여 현재 Cycle을 자신의 기준선에서 제외하는 방식이 설명되어 있습니다.

WEAK SUPERVISION

실제 파손 정답을 대신한 Teacher

Spindle·Servo·RPM·Feed·Offset·Cycle 변화에 물리규칙을 적용하여 0–100 Weak Label을 만듭니다. MLP는 이 점수를 학습하며, 실제 파손 이벤트를 정답으로 학습한 모델과 구분합니다.

A3 · §2–10·14

v6 Weak Label 계산과 모델 입력의 상세 
base = 0.30 × spindle_z + 0.25 × servo_z
     + 0.10 × rpm + 0.10 × feed
     + 0.07 × wear + 0.05 × geometry
     + 0.08 × cycle_instability

anomaly_score = base / 0.95 + 2.50 × spindle_collapse
logit = 1.20 × (anomaly_score − 2.40)
Weak Label = 100 / (1 + exp(−logit))

Tool Usage의 5% 기여를 제거한 뒤 나머지 7개 신호의 상대 비율을 유지하도록 재정규화했습니다. 기본 Feature는 25개이며 iot_seq·O-NUM·Tool No 범주의 One-Hot 수에 따라 총 입력 차원은 달라집니다. 35개는 이번 학습 실행의 값이지 모든 향후 데이터의 고정 차원이 아닙니다.

A3 · §4–5 / A2 · §1

재추론에서도 학습과 같은 문맥 유지

MODEL 또는 MAIN_SEQ가 바뀌면 최근 최대 80 main_seq의 Raw를 다시 읽어 Cycle과 Rolling Feature를 재구성합니다. 최신 한 행만 계산해서는 이전 10 Cycle의 기준선을 재현할 수 없기 때문입니다.

최신 Cycle의 sample_count가 이전 10 Cycle 중앙값의 60% 미만이면 진행 중일 가능성이 있다고 보고 직전 완료 Cycle을 사용합니다. 이는 문서의 보호 조건이며 실제 완료 상태를 직접 확인하는 확정 신호와는 구분합니다.

학습과 Pi 전처리의 일치가 운영의 핵심입니다. 가이드에는 metadata·scaler의 Feature 순서와 TFLite 입력차원 확인이 명시되어 있습니다. v6 재학습 뒤에는 기존 36차원이 아니라 새 모델 차원과 맞는지 확인해야 합니다.
